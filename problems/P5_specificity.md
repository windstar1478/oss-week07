# P5. 우선순위 예측하기 — `p5: specificity`

한 요소에 여러 규칙이 같은 속성을 정하면 그중 하나만 이깁니다. `p5_quiz.html` 에는 그런 문장이 다섯 개 있습니다. **브라우저로 열기 전에** 각 문장의 글자색을 예측해 적고, 그다음에 열어서 맞혀 봅니다.

틀려도 됩니다. 틀린 예측을 고쳐 쓰지 말고 그대로 둔 채, 확인 결과와 이유를 아래에 따로 적습니다.

## 예측하기 (VS Code)

1. VS Code 에서 `p5_quiz.html` 을 엽니다. 브라우저로는 아직 열지 않습니다.
2. `<style>` 안의 규칙(문제 1 ~ 5)과 `<body>` 안의 문장 다섯 개를 읽습니다. 문장마다 `id`, `class`, `style` 이 무엇인지 봅니다. 맨 위의 `p { color: red; }` 는 문장 다섯 개 모두에 걸린다는 것도 같이 봅니다.
3. `p5_answers.md` 의 표에 문제마다 글자색을 영어 이름(`red`, `blue`, …)으로 적습니다. 문제 4 는 글자 크기도 적습니다.

   판단 기준은 이 순서입니다.
   1. `!important` 가 붙은 선언이 먼저 이깁니다. 단, `!important` 는 그 선언 하나에만 붙습니다.
   2. `style="..."` 로 요소에 직접 쓴 것이 어떤 선택자보다 강합니다.
   3. 우선순위를 (id 개수, class 개수, 태그 개수)로 세어 왼쪽 자리부터 비교합니다.
   4. 우선순위가 같으면 나중에 나온 규칙이 이깁니다.
4. 저장하고 예측만 먼저 커밋합니다. 예측을 먼저 했다는 기록입니다.
   ```
   git add p5_answers.md
   git commit -m "p5: predictions"
   ```

## 확인하기 (브라우저)

5. 파일 탐색기에서 `p5_quiz.html` 을 더블클릭해 엽니다. 문장 다섯 개의 색을 내 예측과 비교합니다.
6. 문제 4 의 글자 크기는 눈으로는 알기 어렵습니다. F12 → **Elements** 에서 문제 4 의 `<p>` 를 누르고 **Computed** 탭에서 `font-size` 를 찾습니다.
7. 같은 화면의 **Styles** 를 보면 진 선언에는 줄이 그어져 있습니다. 예측이 틀린 문제는 여기서 어느 선언이 이기고 졌는지 봅니다.

## 결과 적고 커밋 (VS Code → 터미널)

8. `p5_answers.md` 의 "브라우저로 확인한 뒤" 아래에, 틀린 문제의 번호와 이유를 한 줄씩 적습니다. 예: `2 — .tip 이 나중에 나오지만 .tip.big 은 class 가 2개라서 이긴다.` 다 맞았으면 `모두 맞음` 이라고 적습니다.
9. ```
   git add p5_answers.md
   git commit -m "p5: specificity"
   git push
   ```
10. Pages 를 켜 두었으므로 이 파일도 공개됩니다. `https://<내 ID>.github.io/oss-week07/p5_quiz.html` 을 열어 봅니다. 저장소에 올린 파일은 무엇이든 그 이름으로 주소가 생깁니다.
